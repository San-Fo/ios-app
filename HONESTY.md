# HONESTY.md

> Mandatory disclosure. This file is the single source of truth for **what is
> real vs. faked** in this project. Disclosed shortcuts are fine; hidden ones
> are not. If anything below is unclear, assume the code is authoritative —
> every fake path in the app calls `MockMarker.hit(...)` and logs at runtime.

## 0. TL;DR

- The iOS app ships against the **real backend** (`APIConfiguration.live.useMockData = false`).
  Discovery, search, detail, listings, sale/bidding, deal chat, takeover groups,
  verification, profile, likes/views, **community memories** and **public Q&A**
  are real network calls.
- A **mock mode** exists for offline dev/preview/tests (`useMockData = true`) —
  it is **not** the shipping path.
- A few features have **no backend endpoint** and are honestly stubbed (listed in
  §3). The **tokenized Web3 marketplace is a UI concept stub** with no chain (§4).
- The demo data (20 Hong Kong cafés) was **generated by us and pushed to the real
  server** via the public API using the scripts in `scripts/` (§5). It is real
  server data, but it is synthetic/seeded, not organic user content.

## 1. Fully functional (real backend, no fakery)

These hit the live API (`https://lbi.proxied.zone/api/v1`) and persist:

| Area | What works | Endpoints |
|---|---|---|
| Auth | Apple sign-in (token sent to server for verification), dev sign-in, session restore, logout | `POST /auth/apple`, `/auth/dev`, `/auth/logout`, `GET /me` |
| Profile | Load/edit profile, categories, financial intents, saved businesses | `GET/PATCH /me`, `PUT /me/categories`, `/me/financial-intents`, `/me/saved/{id}` |
| Discovery | Recommended, search, detail (view count auto-increments) | `GET /businesses/recommended`, `/businesses/search`, `/businesses/{id}` |
| Listings | Create business, submit for sale, record financing actions | `POST /businesses`, `/businesses/{id}/sale`, `/businesses/{id}/actions` |
| Sale lifecycle | Sales list, place bid, accept bid, decline-to-retail fallback | `GET /sales`, `POST .../bids`, `.../bids/{id}/accept`, `.../decline-commercial-bids` |
| Deal chat | Conversations, messages (real), polling | `GET /me/conversations`, `/conversations/{id}`, `GET/POST /conversations/{id}/messages` |
| Takeover groups | List/create/join/leave/pledge/submit-offer | `GET/POST /businesses/{id}/takeover-groups`, `.../join`, `.../leave`, `.../pledge`, `.../submit-offer` |
| Verification | User KYC and business KYB | `POST /me/verify`, `/businesses/{id}/verify` |
| Likes | Like a business (not your own) | `POST /businesses/{id}/like` |
| **Community memories** | Post / delete memories; shown on detail; `commentCount` | `POST /businesses/{id}/memories`, `DELETE .../memories/{id}` |
| **Public Q&A** | Ask the owner a public question (owner can answer) | `POST /businesses/{id}/questions` |
| Image upload | Wired through an `ImageUploader` seam (see §3 — currently data-URL) | — |
| **Bookmarks / saved** | Persisted **locally** (device `UserDefaults`) so saving works as a guest/offline and survives relaunch; best-effort mirrored to the server when a real session exists | `PUT/DELETE /me/saved/{id}` (mirror only) |

## 2. Derived on the client (expected, not "fake")

The backend intentionally does not author editorial content; the client derives
it. These fire a `DERIVED` marker even on the real path — that's normal:

- **Business editorial** (`BusinessDTO.toDetail`): `tagline`/`storyHeadline` ←
  `description`; `founderName`/`founderStory` ← embedded `owner`; reward tiers
  empty. **Community memories are real**, not derived.
- **AI memo extras** (`SaleEvaluationDTO`): `confidence`/`recommendedAction`
  derived from the server `verdict`/`score`.
- **Account role / funding chips / listing status**: derived from
  `investorStatus`, `financialIntent` and sale stage.

## 3. Honestly stubbed — NO backend endpoint exists

These tappable controls do **not** silently lie beyond what's noted; each is a
`NO_BACKEND` marker in code. They are real UI awaiting an endpoint:

| Feature | Current behaviour | File |
|---|---|---|
| **Image upload** | No upload endpoint, so images are embedded as base64 `data:` URLs. The `ImageUploader` seam is the single swap point when the endpoint lands. | `LiveImageUploader.upload` |
| **Founder Q&A (takeover)** | `askFounder` echoes locally; also has no UI caller. (Separate from the working business Q&A in §1.) | `LiveTakeoverRepository.askFounder` |
| **Deal status lifecycle** | "Mark payment pending/completed/cancel" menu re-fetches; backend has no status field. | `LiveDealChatRepository.updateStatus` |
| **Verification skip/override** | No skip endpoint; treated as a normal submit. | `LiveVerificationRepository` |
| **`joinTakeover` intent** | No server representation; dropped on save (handled via takeover-group endpoints instead). | `UserIntent.serverIntent` |

There is **no reviews/star-rating feature** — by backend decision. "Comments"
are called **memories** and are real (§1).

## 4. Tokenized Web3 marketplace — UI CONCEPT STUB (no chain)

`TokenMarketplaceView` (verified-commercial-investor tab) is an **example stub**:
small/medium businesses shown as tradable on-chain tokens.

- **Entirely in-memory sample data.** No wallet, no chain, no order book, no
  settlement. Every site fires `MockMarker.hit(.mock, ...)`.
- The "Review order" button **places no order** (it's a concept preview).
- Contract addresses, prices, P/L and sparklines are illustrative.

This is disclosed as a forward-looking concept, not a working feature.

## 5. Demo data is seeded by us (synthetic, but on the real server)

The Hong Kong businesses visible in the app were **generated by us** (the cafés
inspired by scraped Google Places listings: names, addresses, coordinates) and
**pushed to the real backend** via the public API. They are genuine server
records, but the content is synthetic:

- **`scripts/seed_cafes.py`** — creates each café: a dedicated dev owner account
  with name + biography, a founder-story description, district mapped from the
  address, gallery images (public Unsplash coffee photos — *not* the original
  scraped photos, which we don't have), a mixed financial intent
  (sale / revenue-share / donation), verification, professional-sale submission,
  seeded commercial bids from dev "investor" accounts, and social proof (likes +
  views from dev "fan" accounts).
- **`scripts/seed_memories.py`** — posts realistic community memories (2–5 per
  café from distinct dev "neighbour" accounts) and public Q&A (with owner
  answers), all via the real `POST /memories` and `/questions` endpoints.
- **`scripts/seed_varied.py`** — 13 businesses across **all categories**
  (restaurant, cafe, retail, services, wellness, artsAndCrafts) and **all goals**
  to showcase the full app: `sale` (commercial bidding + bids),
  `revenueShareLoan`, `donation` (reward tiers), and a `retail_fallback` (owner
  declined commercial bids → opened to the public + a real takeover group with
  members). Same synthetic-provenance caveats apply (dev owners/investors/fans,
  fabricated figures, stock photos).

What this means honestly:
- The **owners, bidders, likers, commenters and askers are dev/seed accounts**,
  not real members of the public.
- AI sale evaluations on these listings are produced by the **real backend**
  (we did not fake them).
- Bid amounts, prices, founder bios and memory texts are **fabricated** but
  plausible.
- Photos are stock coffee imagery, not the actual venues.

Re-running the scripts is safe; they probe endpoint readiness and skip writes if
the endpoints aren't deployed.

## 6. Mock mode (dev/preview/tests only — not shipped)

With `useMockData = true`, every repository is a `Mock*` class backed by
`SampleData`; nothing hits the network. This drives SwiftUI previews and the unit
test suite. The shipping app uses `.live`. To audit: run live and confirm the
`mock` console category shows no `MOCK`/`PLACEHOLDER`/`NO_BACKEND` lines (only
`DERIVED` is expected).

See `MOCKING.md` for the full per-call marker inventory and backend asks.
